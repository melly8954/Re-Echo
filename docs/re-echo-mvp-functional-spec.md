# Re-Echo 1차 MVP 기능 명세서

## 1. 문서 목적

- 본 문서는 Re-Echo 1차 MVP의 기능 단위 동작 규칙을 정의한다.
- PRD에서 정한 범위를 실제 화면, API, 데이터 설계로 내리기 위한
  기준 문서로 사용한다.

## 2. 문서 범위

- 본 문서는 1차 MVP 기능만 다룬다.
- AI, 음성, 화상, DM, 검색, 멘션은 범위에서 제외한다.

## 3. PRD와의 차이

- PRD:
  - 왜 만드는지
  - 누구를 위한지
  - 어디까지 만들지
  - 성공 기준이 무엇인지
  를 정의한다.
- 기능 명세서:
  - 각 기능이 어떤 규칙으로 동작하는지
  - 누가 무엇을 할 수 있는지
  - 어떤 예외가 발생하는지
  - 화면과 상태가 어떻게 바뀌는지
  를 정의한다.

## 4. 공통 규칙

- 서비스 형태는 여러 조직이 사용하는 SaaS형이다.
- 사용자 1명은 여러 워크스페이스를 생성하고 참여할 수 있다.
- 인증은 소셜 로그인만 지원한다.
  - Google
  - Kakao
  - GitHub
- 로그인 후 최초 진입 사용자는 온보딩 플로우로 이동한다.
- 모든 날짜/시간은 서버 기준 UTC 저장, 화면에서는 사용자 기준
  로컬 시간으로 표시한다.

## 5. 역할 정의

### 5.1 소유자

- 워크스페이스 생성자
- 관리자 임명 가능
- 관리자 해제 가능
- 워크스페이스 보관 가능
- 워크스페이스 복원 가능

### 5.2 관리자

- 채널 생성 가능
- 초대 링크 발급 가능
- 비공개 채널 멤버 관리 가능
- 멤버 강제 제거 가능
- 메시지 삭제 가능
- 채널 보관 가능
- 채널 복원 가능

### 5.3 일반 멤버

- 공개 채널 참여 가능
- 비공개 채널은 초대받은 경우만 참여 가능
- 메시지 작성 가능
- 본인 메시지 수정 가능
- 자진 탈퇴 가능

## 6. 인증 기능

### 6.1 소셜 로그인

- 사용자는 Google, Kakao, GitHub 중 하나를 선택해 로그인한다.
- 로그인 성공 시 시스템은 사용자 계정을 생성하거나 기존 계정에
  연결한다.
- 이메일이 동일한 경우 계정 통합 정책은 추후 별도 정의가 필요하다.
  - 1차 MVP에서는 `provider + provider_user_id`를 기본 식별값으로
    보는 것이 안전하다.

### 6.2 로그인 이후 이동

- 참여 중인 워크스페이스가 없으면:
  - 워크스페이스 생성 또는 초대 링크 합류 화면으로 이동
- 참여 중인 워크스페이스가 있으면:
  - 최근 접속 워크스페이스로 이동

## 7. 워크스페이스 기능

### 7.1 워크스페이스 생성

- 로그인 사용자는 워크스페이스를 여러 개 생성할 수 있다.
- 생성 입력값:
  - 워크스페이스 이름
  - 선택적 설명
- 생성 성공 시:
  - 생성자는 소유자가 된다.
  - 기본 채널 `#general`이 자동 생성된다.
  - 생성자는 `#general`에 자동 참여된다.

### 7.2 워크스페이스 목록

- 사용자는 자신이 속한 워크스페이스 목록을 볼 수 있다.
- 목록에는 최소 다음 정보가 필요하다.
  - 워크스페이스 이름
  - 내 역할
  - 최근 메시지 여부 또는 최근 접속 정보

### 7.3 워크스페이스 보관

- 소유자만 워크스페이스를 보관할 수 있다.
- 보관 시:
  - 일반 목록에서 숨김 처리
  - `archived_at`
  - `delete_scheduled_at = archived_at + 15일`
  를 기록한다.
- 보관 기간 15일 내에는 복원 가능하다.
- 15일이 지나면 자동 삭제 대상이 된다.

### 7.4 워크스페이스 복원

- 보관된 워크스페이스는 15일 내 소유자만 복원할 수 있다.
- 복원 시:
  - 숨김 해제
  - 삭제 예정 정보 제거

### 7.5 워크스페이스 자동 삭제

- 배치 작업이 삭제 예정 시간이 지난 워크스페이스를 정리한다.
- 삭제 시 연관 데이터는 함께 제거되어야 한다.
  - 채널
  - 채널 멤버십
  - 메시지
  - 파일 메타데이터
  - 안읽음 상태
- 실제 파일은 스토리지에서도 삭제 처리되어야 한다.

## 8. 관리자 기능

### 8.1 관리자 임명

- 소유자만 관리자 권한을 부여할 수 있다.
- 일반 멤버를 관리자로 승격할 수 있다.

### 8.2 관리자 해제

- 소유자만 관리자 권한을 해제할 수 있다.
- 소유자 자신은 일반 관리자 해제 플로우로 변경되지 않는다.

## 9. 초대 기능

### 9.1 초대 링크 발급

- 소유자/관리자만 초대 링크 발급 가능
- 초대 링크는 워크스페이스 기준으로 관리한다.
- 새 링크를 발급하면 기존 활성 링크는 자동 무효화된다.
- 링크 만료 시간은 발급 후 24시간이다.

### 9.2 초대 링크 사용

- 사용자는 초대 링크를 통해 워크스페이스에 합류할 수 있다.
- 링크가 유효하지 않은 경우:
  - 만료
  - 무효화
  - 존재하지 않음
  에 대한 안내를 보여준다.

### 9.3 강제 제거된 멤버 제한

- 강제 제거된 멤버는 같은 워크스페이스에 재초대할 수 없다.
- 따라서 초대 링크가 유효하더라도 서버에서 가입을 거부해야 한다.

## 10. 멤버십 기능

### 10.1 워크스페이스 합류

- 합류 성공 시 워크스페이스 멤버로 등록된다.
- 기본 역할은 일반 멤버이다.
- `#general`에는 자동 참여된다.

### 10.2 자진 탈퇴

- 일반 멤버와 관리자는 자진 탈퇴 가능하다.
- 소유자 탈퇴는 단순 탈퇴보다 소유권 처리 문제가 있으므로
  1차 MVP에서는 제한하거나 별도 처리 규칙이 필요하다.
  - 안전한 기본안: 소유자는 탈퇴 불가, 보관만 가능

### 10.3 강제 제거

- 소유자/관리자는 멤버를 강제 제거할 수 있다.
- 강제 제거 대상자는:
  - 워크스페이스 접근 불가
  - 채널 접근 불가
  - 재초대 불가

## 11. 채널 기능

### 11.1 채널 종류

- 공개 채널
- 비공개 채널

### 11.2 기본 채널

- 각 워크스페이스에는 `#general`이 자동 생성된다.
- 모든 신규 멤버는 `#general`에 자동 참여한다.

### 11.3 공개 채널 생성

- 관리자만 생성 가능
- 입력값:
  - 채널명
  - 공개 여부
  - 선택적 설명

### 11.4 비공개 채널 생성

- 관리자만 생성 가능
- 생성 후 초기 멤버를 지정할 수 있어야 한다.
- 비공개 채널은 초대된 멤버만 조회/입장 가능하다.

### 11.5 공개 채널 참여

- `#general` 외 공개 채널은 자동 참여되지 않는다.
- 멤버가 직접 참여하는 구조가 필요하다.

### 11.6 비공개 채널 멤버 관리

- 모든 관리자가 멤버 추가/제거 가능하다.
- 일반 멤버는 비공개 채널 멤버 관리 불가

### 11.7 채널 보관

- 관리자만 채널 보관 가능
- 보관 시:
  - 일반 목록에서 숨김
  - `archived_at`
  - `delete_scheduled_at = archived_at + 15일`
  기록

### 11.8 채널 복원

- 관리자만 15일 내 복원 가능

### 11.9 채널 자동 삭제

- 보관 후 15일 경과 시 자동 삭제
- 연관 메시지, 파일 메타데이터, 멤버십, 안읽음 상태 정리 필요

## 12. 메시지 기능

### 12.1 메시지 작성

- 채널 멤버만 메시지 작성 가능
- 메시지 타입:
  - 텍스트
  - 파일 첨부 포함 메시지

### 12.2 메시지 정렬

- 채널 입장 시 최신 메시지 기준으로 진입한다.
- 화면은 하단 중심 채팅 UX를 따른다.
- 사용자는 위로 스크롤하며 과거 메시지를 로드한다.

### 12.3 메시지 전송 상태

- 전송 중
- 전송 성공
- 전송 실패
- 실패 시 재전송 가능

### 12.4 입력 중 표시

- 같은 채널 내 다른 사용자가 입력 중일 때 상태 표시
- 너무 오래 지속되지 않도록 TTL 기반 만료 처리 필요

### 12.5 메시지 수정

- 본인 메시지만 수정 가능
- 수정 여부가 화면에 표시되는 것이 바람직하다.

### 12.6 메시지 삭제

- 관리자는 모든 메시지 삭제 가능
- 일반 멤버는 본인 삭제가 아니라 본인 수정만 허용
  - 현재 확정 범위 기준으로는 본인 삭제는 없음

## 13. 파일 기능

### 13.1 업로드 방식

- Presigned URL 기반 직접 업로드
- 흐름:
  1. 클라이언트가 업로드 요청
  2. 서버가 권한 확인
  3. 서버가 presigned URL 발급
  4. 클라이언트가 R2로 직접 업로드
  5. 업로드 완료 후 서버에 메타데이터 등록

### 13.2 다운로드 방식

- Presigned URL 기반 직접 다운로드
- 권한 확인 후 짧은 만료 시간의 다운로드 URL 발급

### 13.3 파일 제한

- 파일 종류는 대체로 허용
- 최대 용량은 20MB

### 13.4 미리보기

- 이미지 파일만 채팅창에서 미리보기
- 비이미지 파일은 파일명, 크기, 다운로드 액션 중심으로 표시

### 13.5 파일 메타데이터

- DB에는 최소 다음 정보를 저장한다.
  - 파일 ID
  - 원본 파일명
  - 저장 키
  - MIME 타입
  - 파일 크기
  - 업로더
  - 연결 메시지 ID

## 14. 프로필 기능

### 14.1 전역 계정 프로필

- 소셜 로그인 정보로 기본 계정 생성

### 14.2 워크스페이스별 프로필

- 닉네임 수정 가능
- 프로필 이미지 수정 가능
- 워크스페이스마다 다른 표시 이름/이미지 사용 가능

## 15. 안읽음/알림 기능

### 15.1 안읽음

- 채널 단위 안읽음만 지원
- 각 채널별 새 메시지 개수 또는 새 메시지 존재 여부를 표시

### 15.2 알림

- 채널 목록 배지만 제공
- 인앱 토스트 없음
- 브라우저 푸시 없음

## 16. 제외 기능 명세

- DM 없음
- 메시지 검색 없음
- 멘션 없음
- AI 협업 비서 없음
- 음성 협업 없음
- 화상 협업 없음

## 17. 주요 예외 처리

### 17.1 만료된 초대 링크

- 합류 불가
- 만료 안내 표시

### 17.2 무효화된 초대 링크

- 합류 불가
- 최신 링크 요청 안내

### 17.3 강제 제거된 사용자 재진입

- 링크가 유효해도 가입 불가

### 17.4 보관된 채널 접근

- 일반 사용자 접근 불가
- 관리자만 복원 가능

### 17.5 파일 용량 초과

- 업로드 시작 전 차단
- 20MB 초과 안내 표시

### 17.6 권한 없는 채널 접근

- 비공개 채널 미참여자는 접근 불가

## 18. 화면 단위 최소 구성

### 18.1 로그인 화면

- Google 로그인
- Kakao 로그인
- GitHub 로그인

### 18.2 워크스페이스 선택/생성 화면

- 참여 워크스페이스 목록
- 새 워크스페이스 생성
- 초대 링크 합류

### 18.3 메인 협업 화면

- 워크스페이스 전환
- 채널 목록
- 안읽음 배지
- 메시지 영역
- 파일 첨부
- 입력창

### 18.4 채널 생성 화면

- 공개/비공개 선택
- 채널명 입력

### 18.5 멤버 관리 화면

- 멤버 목록
- 역할 표시
- 관리자 지정/해제
- 강제 제거

### 18.6 초대 관리 화면

- 현재 활성 링크 확인
- 링크 재발급
- 만료 시간 표시

### 18.7 프로필 설정 화면

- 워크스페이스별 닉네임 수정
- 워크스페이스별 프로필 이미지 수정

## 19. 개발 우선순위 제안

1. 인증
2. 워크스페이스 생성/선택
3. 기본 채널 `#general`
4. 실시간 메시지
5. 초대 링크 합류
6. 공개/비공개 채널
7. 역할/권한
8. 파일 업로드와 이미지 미리보기
9. 안읽음 배지
10. 보관/복원/자동 삭제

  - ERD 초안
  - API 목록
  - 화면 흐름도
  - Sprint 단위 개발 계획
