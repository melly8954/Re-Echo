# Re-Echo App Design

이 문서는 Re-Echo 프론트엔드 화면 설계와 UI 구현 기준을 정의한다.

`docs/coding-convention.md`가 코드 구조와 작성 규칙을 다룬다면,
이 문서는 화면의 공통 디자인 방향, 접근성, 반응형 기준, 화면별 UI
규칙을 다룬다.

아직 확정되지 않은 화면별 상세 UI 규칙은 이 문서에 임의로 추가하지
않고, 인터뷰를 통해 확정된 뒤 보완한다.

## 1. 문서 범위

이 문서는 다음 순서로 기준을 정의한다.

1. 공통 디자인 기준
2. 접근성 기준
3. 반응형 기준
4. 화면별 UI 규칙

현재 문서에서는 공통 디자인, 접근성, 반응형 기준까지만 확정한다.
화면별 UI 규칙은 후속 인터뷰에서 확정한다.

## 2. 공통 디자인 기준

### 2.1 UI Tone

Re-Echo는 업무용이지만 가볍고 친근한 협업 도구의 톤을 사용한다.

채팅과 워크스페이스 이동이 빠르고 편해야 하므로, 과하게 장식적인
랜딩 페이지 느낌보다 실제 협업 화면의 가독성과 반복 사용성을
우선한다.

### 2.2 Color Direction

기본 색상 방향은 밝은 중립 배경과 초록/청록 포인트를 사용한다.

- 화면 배경은 흰색과 밝은 회색 계열을 중심으로 한다.
- 주요 액션, 활성 상태, 선택 상태는 초록/청록 계열로 강조한다.
- 메시지, 채널 목록, 입력창의 가독성을 우선한다.
- 배경이나 장식 요소를 과하게 컬러풀하게 만들지 않는다.

### 2.3 Density

기본 화면 밀도는 적당히 촘촘한 협업 도구 밀도를 사용한다.

메시지 목록과 채널 목록은 한 화면에 충분히 많이 보이도록 하되,
입력창, 주요 버튼, 모달은 여백을 확보해 조작성을 유지한다.

### 2.4 Layout

데스크톱 기본 레이아웃은 왼쪽 채널 사이드바와 오른쪽 메시지 본문을
사용한다.

워크스페이스 전환, 사용자 메뉴, 설정 진입은 상단 영역 또는 메뉴에서
처리한다. 초기 MVP에서는 별도의 워크스페이스 전용 세로 바를 두지
않는다.

### 2.5 Shape

버튼, 입력창, 메뉴, 패널은 살짝 둥근 스타일을 사용한다.

- 기본 radius는 `6px`~`8px` 범위를 사용한다.
- 작은 버튼이나 배지는 `4px`~`6px` 범위를 사용한다.
- 모달이나 큰 패널도 `8px`을 기본 상한으로 둔다.
- 업무용 도구의 명확함을 유지하기 위해 과하게 둥글게 만들지 않는다.

### 2.6 Typography

기본 글자 크기는 일반적인 협업 도구 수준으로 사용한다.

- 기본 본문 글자 크기는 `14px`~`15px`를 사용한다.
- 채팅 메시지는 `15px`를 기본으로 하여 장시간 읽기 피로를 줄인다.
- 사이드바, 보조 텍스트, 메타 정보는 `12px`~`13px`를 사용한다.
- 페이지 제목이나 모달 제목은 `18px`~`24px` 범위에서 사용한다.
- 행간은 메시지 본문 기준 `1.45`~`1.6`을 사용한다.

### 2.7 State Expression

상태 표현은 배지, 배경색, 아이콘을 함께 사용하는 명확한 방식을
사용한다.

읽지 않은 메시지, 선택된 채널, 전송 실패, 연결 끊김, 권한 오류처럼
사용자가 즉시 알아야 하는 상태는 색상만으로 구분하지 않는다.

강한 애니메이션이나 큰 경고 영역은 연결 끊김, 전송 실패처럼 즉시
조치가 필요한 상황에만 제한적으로 사용한다.

## 3. 접근성 기준

Re-Echo의 접근성 기준은 협업 도구 권장 수준으로 잡는다.

### 3.1 기본 원칙

- semantic HTML을 우선 사용한다.
- 버튼과 링크의 역할을 혼용하지 않는다.
- 입력 요소에는 명확한 label을 제공한다.
- focus 표시를 제거하지 않는다.
- 색상만으로 상태를 구분하지 않는다.

### 3.2 키보드 조작

주요 기능은 키보드만으로 조작할 수 있어야 한다.

- `Tab`으로 주요 인터랙션 요소를 순서대로 이동할 수 있어야 한다.
- `Enter` 또는 `Space`로 버튼성 동작을 실행할 수 있어야 한다.
- `Esc`는 모달, drawer, 드롭다운 같은 임시 UI를 닫는 동작에 사용한다.

### 3.3 Modal, Drawer, Menu

모달과 drawer는 focus trap을 지원한다.

- 모달이나 drawer가 열리면 focus는 열린 영역 안에 머문다.
- 닫기 버튼과 `Esc`로 닫을 수 있어야 한다.
- 닫힌 뒤에는 가능하면 열기 전 요소로 focus를 되돌린다.

드롭다운, 메뉴, 선택된 채널, 로딩, 오류 상태는 필요한 경우
`aria-*` 상태값을 제공한다.

### 3.4 Status Accessibility

읽지 않은 메시지, 오류, 로딩, 연결 끊김 같은 상태는 화면 리더와
키보드 사용자도 이해할 수 있어야 한다.

상태는 텍스트, 아이콘, 배지, 배경색을 조합해 표현한다.

## 4. 반응형 기준

### 4.1 Breakpoint

Re-Echo는 다음 화면 크기 기준을 사용한다.

```text
Mobile: < 768px
Tablet: 768px ~ 1023px
Laptop: 1024px ~ 1439px
Desktop: >= 1440px
```

구간을 세분화하되, 모든 구간에서 완전히 다른 UI를 만들지는 않는다.
레이아웃 전환 기준을 명확히 하기 위한 구분으로 사용한다.

### 4.2 Mobile

모바일에서는 메시지 화면을 기본 화면으로 사용한다.

채널 목록은 상단의 메뉴 버튼을 통해 drawer로 연다. drawer가 열리면
배경 스크롤을 막고, `Esc` 또는 닫기 버튼으로 닫을 수 있어야 한다.

채널을 선택하면 drawer를 닫고 해당 메시지 화면으로 이동한다.

### 4.3 Tablet

Tablet 구간에서는 화면 방향에 따라 레이아웃을 다르게 적용한다.

- 세로 방향에서는 모바일과 동일하게 메시지 화면을 기본으로 하고,
  채널 목록은 drawer로 제공한다.
- 가로 방향에서는 데스크톱과 동일하게 채널 사이드바와 메시지 본문을
  함께 노출한다.

### 4.4 Laptop and Desktop

Laptop과 Desktop에서는 왼쪽 채널 사이드바와 오른쪽 메시지 본문을
기본 구조로 사용한다.

Desktop에서는 Laptop 구조를 유지하되, 여백, 사이드바 폭, 메시지
본문 최대 너비를 안정적으로 조정한다.

## 5. 화면별 UI 규칙

화면별 UI 규칙은 아직 확정하지 않았다.

후속 인터뷰에서 로그인, 워크스페이스, 채널, 메시지, 초대 링크,
파일 업로드 화면의 UI 규칙을 순서대로 확정한 뒤 이 섹션에 추가한다.
