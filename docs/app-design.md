# Re-Echo App Design

이 문서는 Re-Echo 프론트엔드 화면 설계와 UI 구현 기준을 정의한다.

`docs/coding-convention.md`가 코드 구조와 작성 규칙을 다룬다면,
이 문서는 화면의 공통 디자인 방향, 접근성, 반응형 기준, 화면별 UI
규칙을 다룬다.

아직 확정되지 않은 화면별 상세 UI 규칙은 이 문서에 임의로 추가하지
않고, 인터뷰를 통해 확정된 뒤 보완한다.

## 1. 문서 범위

이 문서는 다음 순서로 기준을 정의한다.

1. 공통 디자인 기준
2. 접근성 기준
3. 반응형 기준
4. 화면별 UI 규칙

현재 문서에서는 공통 디자인, 접근성, 반응형 기준까지만 확정한다.
화면별 UI 규칙은 후속 인터뷰에서 확정한다.

## 2. 공통 디자인 기준

### 2.1 UI Tone

Re-Echo는 업무용이지만 가볍고 친근한 협업 도구의 톤을 사용한다.

채팅과 워크스페이스 이동이 빠르고 편해야 하므로, 과하게 장식적인
랜딩 페이지 느낌보다 실제 협업 화면의 가독성과 반복 사용성을
우선한다.

### 2.2 Color Direction

기본 색상 방향은 밝은 중립 배경과 초록/청록 포인트를 사용한다.

- 화면 배경은 흰색과 밝은 회색 계열을 중심으로 한다.
- 주요 액션, 활성 상태, 선택 상태는 초록/청록 계열로 강조한다.
- 메시지, 채널 목록, 입력창의 가독성을 우선한다.
- 배경이나 장식 요소를 과하게 컬러풀하게 만들지 않는다.

### 2.3 Density

기본 화면 밀도는 적당히 촘촘한 협업 도구 밀도를 사용한다.

메시지 목록과 채널 목록은 한 화면에 충분히 많이 보이도록 하되,
입력창, 주요 버튼, 모달은 여백을 확보해 조작성을 유지한다.

### 2.4 Layout

데스크톱 기본 레이아웃은 왼쪽 채널 사이드바와 오른쪽 메시지 본문을
사용한다.

워크스페이스 전환, 사용자 메뉴, 설정 진입은 상단 영역 또는 메뉴에서
처리한다. 초기 MVP에서는 별도의 워크스페이스 전용 세로 바를 두지
않는다.

### 2.5 Shape

버튼, 입력창, 메뉴, 패널은 살짝 둥근 스타일을 사용한다.

- 기본 radius는 `6px`~`8px` 범위를 사용한다.
- 작은 버튼이나 배지는 `4px`~`6px` 범위를 사용한다.
- 모달이나 큰 패널도 `8px`을 기본 상한으로 둔다.
- 업무용 도구의 명확함을 유지하기 위해 과하게 둥글게 만들지 않는다.

### 2.6 Typography

기본 글자 크기는 일반적인 협업 도구 수준으로 사용한다.

- 기본 본문 글자 크기는 `14px`~`15px`를 사용한다.
- 채팅 메시지는 `15px`를 기본으로 하여 장시간 읽기 피로를 줄인다.
- 사이드바, 보조 텍스트, 메타 정보는 `12px`~`13px`를 사용한다.
- 페이지 제목이나 모달 제목은 `18px`~`24px` 범위에서 사용한다.
- 행간은 메시지 본문 기준 `1.45`~`1.6`을 사용한다.

### 2.7 State Expression

상태 표현은 배지, 배경색, 아이콘을 함께 사용하는 명확한 방식을
사용한다.

읽지 않은 메시지, 선택된 채널, 전송 실패, 연결 끊김, 권한 오류처럼
사용자가 즉시 알아야 하는 상태는 색상만으로 구분하지 않는다.

강한 애니메이션이나 큰 경고 영역은 연결 끊김, 전송 실패처럼 즉시
조치가 필요한 상황에만 제한적으로 사용한다.

## 3. 접근성 기준

Re-Echo의 접근성 기준은 협업 도구 권장 수준으로 잡는다.

### 3.1 기본 원칙

- semantic HTML을 우선 사용한다.
- 버튼과 링크의 역할을 혼용하지 않는다.
- 입력 요소에는 명확한 label을 제공한다.
- focus 표시를 제거하지 않는다.
- 색상만으로 상태를 구분하지 않는다.

### 3.2 키보드 조작

주요 기능은 키보드만으로 조작할 수 있어야 한다.

- `Tab`으로 주요 인터랙션 요소를 순서대로 이동할 수 있어야 한다.
- `Enter` 또는 `Space`로 버튼성 동작을 실행할 수 있어야 한다.
- `Esc`는 모달, drawer, 드롭다운 같은 임시 UI를 닫는 동작에 사용한다.

### 3.3 Modal, Drawer, Menu

모달과 drawer는 focus trap을 지원한다.

- 모달이나 drawer가 열리면 focus는 열린 영역 안에 머문다.
- 닫기 버튼과 `Esc`로 닫을 수 있어야 한다.
- 닫힌 뒤에는 가능하면 열기 전 요소로 focus를 되돌린다.

드롭다운, 메뉴, 선택된 채널, 로딩, 오류 상태는 필요한 경우
`aria-*` 상태값을 제공한다.

### 3.4 Status Accessibility

읽지 않은 메시지, 오류, 로딩, 연결 끊김 같은 상태는 화면 리더와
키보드 사용자도 이해할 수 있어야 한다.

상태는 텍스트, 아이콘, 배지, 배경색을 조합해 표현한다.

## 4. 반응형 기준

### 4.1 Breakpoint

Re-Echo는 다음 화면 크기 기준을 사용한다.

```text
Mobile: < 768px
Tablet: 768px ~ 1023px
Laptop: 1024px ~ 1439px
Desktop: >= 1440px
```

구간을 세분화하되, 모든 구간에서 완전히 다른 UI를 만들지는 않는다.
레이아웃 전환 기준을 명확히 하기 위한 구분으로 사용한다.

### 4.2 Mobile

모바일에서는 메시지 화면을 기본 화면으로 사용한다.

채널 목록은 상단의 메뉴 버튼을 통해 drawer로 연다. drawer가 열리면
배경 스크롤을 막고, `Esc` 또는 닫기 버튼으로 닫을 수 있어야 한다.

채널을 선택하면 drawer를 닫고 해당 메시지 화면으로 이동한다.

### 4.3 Tablet

Tablet 구간에서는 화면 방향에 따라 레이아웃을 다르게 적용한다.

- 세로 방향에서는 모바일과 동일하게 메시지 화면을 기본으로 하고,
  채널 목록은 drawer로 제공한다.
- 가로 방향에서는 데스크톱과 동일하게 채널 사이드바와 메시지 본문을
  함께 노출한다.

### 4.4 Laptop and Desktop

Laptop과 Desktop에서는 왼쪽 채널 사이드바와 오른쪽 메시지 본문을
기본 구조로 사용한다.

Desktop에서는 Laptop 구조를 유지하되, 여백, 사이드바 폭, 메시지
본문 최대 너비를 안정적으로 조정한다.

## 5. 화면별 UI 규칙

이 섹션은 화면별 UI 구현 기준을 정의한다.

### 5.1 Login

로그인 화면은 별도 랜딩형 페이지보다 앱 레이아웃 안에서 로그인을
유도하는 방식으로 구성한다.

비로그인 상태에서는 채널/메시지 앱 레이아웃을 흐릿한 빈 상태로
보여주고, 중앙에 로그인 패널을 표시한다.

- 배경 앱 레이아웃에는 실제 채널명, 메시지, 사용자 정보를 노출하지
  않는다.
- 배경에는 skeleton, placeholder, 비식별 텍스트만 사용한다.
- 로그인 패널에는 Re-Echo의 짧은 설명과 소셜 로그인 버튼을 배치한다.
- 설명은 제품 소개보다 로그인 후 사용할 협업 채팅 경험을 짧게
  안내하는 수준으로 제한한다.

### 5.2 First Entry After Login

로그인 후 사용자가 접근 가능한 최근 워크스페이스가 있으면 해당
워크스페이스로 바로 진입한다.

최근 워크스페이스가 없거나 접근 권한이 사라진 경우에는 워크스페이스
생성/참여 선택 화면을 보여준다.

초대 링크로 진입한 경우에는 초대된 워크스페이스 참여 흐름을 우선한다.

### 5.3 Workspace Empty State

사용자가 접근 가능한 워크스페이스가 없을 때는 생성과 참여를 같은
우선순위로 제공한다.

“새 워크스페이스 만들기”와 “초대 링크로 참여”는 나란한 카드 또는
동일한 시각적 비중의 선택지로 표시한다.

- 생성 카드는 워크스페이스 이름 입력 흐름으로 연결한다.
- 참여 카드는 초대 링크 입력 또는 초대 링크 검증 흐름으로 연결한다.

### 5.4 Channel List

채널 목록은 단순한 사이드바 목록을 기본으로 한다.

공개 채널과 비공개 채널은 아이콘으로 구분한다. 채널 수가 적을 때는
하나의 목록처럼 보이게 유지하고, 채널 수가 늘어날 경우 공개/비공개
라벨을 사용해 탐색성을 높인다.

즐겨찾기나 최근 채널 그룹은 MVP 기본 규칙에 포함하지 않는다.

### 5.5 Channel State

채널 목록에서는 선택된 채널, 읽지 않은 채널, 읽지 않은 개수를 함께
표현한다.

선택된 채널은 연한 청록 배경, 왼쪽 accent bar 또는 아이콘 강조,
명확한 텍스트 색상과 weight로 표현한다.

읽지 않은 채널은 채널명을 굵게 표시하고 왼쪽 작은 점을 사용할 수
있다. 읽지 않은 개수는 오른쪽 숫자 배지로 표시하며, `99`개 초과는
`99+`로 표시한다.

선택 상태와 읽지 않은 상태가 겹치면 선택 배경을 우선하고, 읽지 않은
숫자 배지는 유지한다. 왼쪽 점이 선택 accent bar와 겹치면 생략할 수
있다.

멘션 전용 강조 규칙은 MVP 범위에 포함하지 않는다.

### 5.6 Message List

메시지 목록은 행 기반 레이아웃을 기본으로 한다.

같은 작성자의 연속 메시지는 하나의 메시지 그룹으로 묶고, 첫 메시지에만
작성자명, 아바타, 대표 시간을 표시한다.

같은 작성자라도 날짜가 바뀌거나 일정 시간 이상 간격이 있으면 새
메시지 그룹으로 분리한다.

각 메시지 행에는 hover 시 상세 시간, 작업 메뉴, 전송 상태를 표시할 수
있다.

내가 보낸 메시지, 임시 메시지, 전송 실패 메시지는 필요한 경우 연한
배경 또는 제한적인 말풍선형 강조를 사용할 수 있다.

채널 대화의 가독성을 위해 모든 메시지를 기본 말풍선 형태로 표시하지
않는다.

### 5.7 Message Composer

메시지 입력창은 여러 줄 입력이 가능한 composer 형태로 제공한다.

기본 높이는 한 줄 입력에 맞추되, 입력 내용이 길어지면 일정 높이까지
확장된다.

- 파일 첨부 버튼은 입력창 왼쪽 또는 하단 액션 영역에 둔다.
- 전송 버튼은 입력창 오른쪽에 배치한다.
- `Enter`는 전송, `Shift+Enter`는 줄바꿈을 기본 동작으로 한다.

### 5.8 File Attachment

파일을 선택하면 메시지 입력창 위에 첨부 미리보기 영역을 표시한다.

- 이미지 파일은 작은 썸네일로 보여준다.
- 일반 파일은 파일명, 확장자, 용량을 포함한 파일 카드로 보여준다.
- 각 첨부 항목에는 제거 버튼을 제공한다.
- 업로드 진행률과 실패 상태는 필요 시 미리보기 항목 안에서 표시한다.

### 5.9 Typing Indicator

입력 중 표시는 메시지 목록 하단, composer 바로 위에 표시한다.

“OOO님이 입력 중...” 문구와 작은 점 애니메이션을 함께 사용한다.

여러 명이 입력 중이면 최대 2명까지 이름을 표시하고, 그 이상은 “외
N명” 형태로 축약한다.

입력 중 표시가 없을 때도 composer 위치가 크게 흔들리지 않도록 영역
높이를 안정적으로 관리한다.

채널 헤더에는 입력 중 상태를 표시하지 않는다.

### 5.10 Invite Link

초대 링크 화면은 참여 전에 사용자가 어떤 워크스페이스에 들어가는지
확인할 수 있게 구성한다.

워크스페이스 이름, 초대한 사람, 초대 링크 만료 여부를 표시한다.

유효한 초대라면 “참여하기” 버튼을 제공한다. 만료되었거나 유효하지
않은 초대라면 참여 버튼을 비활성화하고 사유를 명확히 안내한다.

로그인이 필요한 경우에는 로그인 후 같은 초대 흐름으로 돌아올 수
있어야 한다.

### 5.11 Error and Empty State

오류와 빈 상태는 원인 설명과 다음 행동을 함께 제공한다.

일시적인 오류는 짧은 문구와 재시도 버튼으로 단순하게 표시한다.

빈 상태나 온보딩 성격의 화면에는 가벼운 아이콘을 사용할 수 있다.

권한 오류, 만료, 유효하지 않은 초대처럼 사용자가 조치해야 하는 상태는
원인을 명확히 설명하고 다음 행동 버튼을 제공한다.

큰 일러스트나 과한 장식은 사용하지 않는다.

### 5.12 Loading and Skeleton

로딩 상태는 영역별 skeleton을 기본으로 한다.

채널 목록, 메시지 목록, 워크스페이스 카드처럼 반복 구조가 있는 영역은
실제 레이아웃과 유사한 skeleton을 표시한다.

짧은 로딩은 불필요한 깜빡임을 줄이기 위해 즉시 표시하지 않을 수 있다.

버튼 클릭 후 처리 중 상태는 버튼 내부 spinner 또는 disabled 상태로
표시한다.

전체 화면 spinner는 초기 앱 부팅이나 인증 확인처럼 화면 전체가 준비되지
않은 경우에만 사용한다.

### 5.13 Toast and Inline Feedback

짧고 전역적인 피드백은 오른쪽 아래 toast로 표시한다.

복사 완료, 저장 완료, 초대 링크 복사 완료처럼 사용자가 추가 조치를
하지 않아도 되는 상태는 toast를 사용한다.

입력값 오류, 초대 링크 오류, 메시지 전송 실패처럼 사용자가 바로
조치해야 하는 상태는 해당 입력 영역, 메시지 행, composer 근처에
inline feedback으로 표시한다.

toast는 자동으로 사라질 수 있지만, 오류 toast는 사용자가 읽을 수
있도록 충분한 시간을 제공한다.

같은 메시지의 toast를 짧은 시간에 중복해서 쌓지 않는다.

### 5.14 Modal and Confirmation

확인 모달은 되돌리기 어렵거나 영향 범위가 큰 작업에만 사용한다.

삭제, 워크스페이스 나가기, 채널 나가기, 초대 링크 재생성, 권한 변경처럼
사용자 또는 다른 구성원에게 영향을 주는 작업은 확인 모달을 사용한다.

일반 저장, 복사, 전송, 입력 오류 같은 작업은 확인 모달 대신 toast 또는
inline feedback으로 처리한다.

확인 모달은 남용하지 않으며, 사용자의 흐름을 끊을 필요가 있는 작업에만
제한한다.

### 5.15 Permission and Disabled State

권한과 비활성 UI는 주요 액션과 숨겨도 되는 기능을 구분해서 처리한다.

사용자가 현재 맥락에서 볼 필요가 있는 주요 액션은 disabled 상태로
표시하고, tooltip 또는 inline text로 이유를 제공한다.

권한이 없어 접근할 수 없는 관리 메뉴, MVP 범위에 없는 기능, 사용자에게
의미 없는 액션은 표시하지 않는다.

disabled 버튼은 hover/focus 시에도 이유를 확인할 수 있어야 한다.

모바일에서는 tooltip 대신 보조 문구나 toast를 사용할 수 있다.

### 5.16 Top Bar Menu

상단바는 워크스페이스 전환과 사용자 메뉴를 분리한다.

상단 왼쪽에는 현재 워크스페이스 이름과 워크스페이스 전환 메뉴를
배치한다.

워크스페이스 전환 메뉴에서는 접근 가능한 워크스페이스 목록과 생성/참여
진입점을 제공한다.

상단 오른쪽에는 사용자 프로필 메뉴를 배치한다.

사용자 메뉴에는 프로필 정보, 설정 진입, 로그아웃을 포함한다.

워크스페이스 맥락의 설정과 사용자 계정 설정은 메뉴 안에서 명확히
구분한다.

모바일에서는 상단 공간이 부족하면 워크스페이스 전환과 사용자 메뉴를
아이콘 버튼 또는 drawer 내부 메뉴로 축약할 수 있다.

### 5.17 Theme

MVP에서는 라이트 모드만 지원한다.

다크 모드는 후속 확장 대상으로 둔다.

색상은 향후 다크 모드 확장이 가능하도록 CSS 변수 기반 token으로
관리한다.
