# Re-Echo 1차 MVP PRD

## 1. 문서 목적

- 본 문서는 Re-Echo 1차 MVP의 제품 목표, 사용자 흐름, 범위,
  제약, 완료 기준을 정의한다.
- 설계, ERD, API, 화면 구조, 개발 우선순위의 기준 문서로 사용한다.

## 2. 제품 개요

- 제품명: Re-Echo
- 제품 성격: 여러 조직이 사용하는 SaaS형 채널 기반 실시간
  협업 서비스
- 1차 MVP 핵심 가치:
  - 팀이 워크스페이스를 만들고
  - 멤버를 초대하고
  - 채널에서 실시간으로 대화하고
  - 파일을 공유하는 기본 협업 경험 제공

## 3. 문제 정의

- 기존 메신저는 개인 대화 중심인 경우가 많아 팀 단위 협업
  구조를 만들기 어렵다.
- 협업 툴은 기능이 많지만 초기 사용 장벽이 높을 수 있다.
- Re-Echo 1차 MVP는 복잡한 AI/음성/화상 기능보다
  채널 중심 협업의 기본 흐름을 빠르게 제공하는 데 집중한다.

## 4. 목표

- 여러 조직이 바로 생성해서 사용할 수 있는 SaaS형 구조를 제공한다.
- 채널 중심의 실시간 협업 경험을 데모 가능 수준으로 완성한다.
- 파일 공유가 가능한 기본 협업 환경을 제공한다.
- 향후 AI, 음성, 화상 기능 확장을 고려할 수 있는 구조를 만든다.

## 5. 비목표

- DM
- 메시지 검색
- 멘션
- RAG 기반 AI 협업 비서
- 음성 협업
- 화상 협업
- 인앱 푸시/브라우저 푸시 알림

## 6. 대상 사용자

- 여러 조직이 사용하는 SaaS형 서비스 사용자
- 팀, 프로젝트 그룹, 조직 단위 협업 사용자
- 채널 기반 커뮤니케이션이 필요한 사용자

## 7. 핵심 사용자 시나리오

1. 사용자는 Google, Kakao, GitHub 중 하나로 로그인한다.
2. 사용자는 새 워크스페이스를 생성한다.
3. 시스템은 기본 채널 `#general`을 자동 생성한다.
4. 소유자 또는 관리자는 24시간 만료 초대 링크를 발급한다.
5. 초대받은 사용자는 워크스페이스에 합류한다.
6. 합류한 사용자는 `#general`에 자동 참여된다.
7. 관리자는 공개 채널 또는 비공개 채널을 생성한다.
8. 사용자는 채널에서 실시간 텍스트 메시지를 주고받는다.
9. 사용자는 파일을 첨부하고, 이미지 파일은 채팅창에서
   미리보기를 확인한다.

## 8. 핵심 기능 범위

### 8.1 인증

- 소셜 로그인 지원
  - Google
  - Kakao
  - GitHub
- 최초 로그인 시 OAuth Provider의 이름과 프로필 이미지를 계정 기본
  프로필로 저장
- 계정 기본 프로필은 워크스페이스가 없는 상태와 새 멤버십의 초기값으로
  사용
- OAuth 로그인 실패 시 내부 원인을 노출하지 않고 로그인 화면으로
  이동하여 재시도를 안내
- 로그인 성공 시 access token은 응답 body로 반환
- 로그인/refresh 응답 헤더로 access token을 전달하지 않음
- refresh token은 HttpOnly cookie로만 전달
- refresh token cookie 정책
  - HttpOnly
  - Secure
  - SameSite=Lax
- refresh 시 access token을 반환
- refresh 시 refresh token도 재발급하여 기존 token을 교체
- 동일 사용자의 다중 브라우저·기기 로그인 세션을 허용
- refresh token은 세션별로 관리하며 logout 시 현재 세션만 무효화
- refresh 요청에서 refresh token 만료 또는 무효는 401과 `AUTH_*`
  비즈니스 예외로 처리
- logout은 멱등하게 처리하며 세션이 이미 종료되었거나 refresh token
  cookie가 없거나 만료·무효 상태여도 `200 OK`를 반환
- logout 요청 시 refresh token cookie는 항상 만료 처리
- logout 응답은 빈 `result`와 성공 메시지를 반환

### 8.2 워크스페이스

- 사용자당 여러 워크스페이스 생성 가능
- 워크스페이스 목록은 사용자의 생성·참여 등록 순서로 노출하며,
  마지막 방문 이후에도 위치를 변경하지 않음
- 로그인 후 최근 방문한 활성 워크스페이스의 홈으로 진입
- 활성 워크스페이스가 없을 때만 워크스페이스 생성과 초대 링크 참여를
  제공하는 빈 상태를 표시
- 워크스페이스 전환은 왼쪽 워크스페이스 레일에서 제공
- 워크스페이스 생성과 초대 링크 참여는 레일 하단 `+` 메뉴에서 제공
- 현재 워크스페이스의 홈과 채널 목록은 워크스페이스 레일과 분리된
  채널 사이드바에서 제공
- 워크스페이스 진입 시 마지막 방문 시각을 갱신
- 워크스페이스 역할 구조
  - 소유자
  - 관리자
  - 일반 멤버
- 워크스페이스에는 항상 1명의 소유자가 있어야 함
- 마지막 소유자는 스스로 관리자 또는 일반 멤버로 변경할 수 없음
- 관리자 임명/해제는 소유자만 가능
- 워크스페이스는 소유자만 보관 가능
- 관리자는 워크스페이스를 보관하거나 복원할 수 없음
- 활성 워크스페이스 재진입 시 워크스페이스 홈으로 진입하고, 채널은
  홈 또는 채널 목록에서 선택
- 워크스페이스 홈에는 전체 참여자 수와 채널별 인원 수를 표시
- 보관된 워크스페이스는 15일 내 복원 가능
- 보관된 워크스페이스 상세에는 복원 가능 여부 `canRestore`를 포함
- 보관된 워크스페이스는 멤버가 홈에서 보관 상태를 확인할 수 있음
- 보관된 워크스페이스에서는 채널 목록과 기존 채널을 노출하지 않음
- 15일 경과 후 자동 삭제

### 8.3 초대

- 소유자/관리자만 초대 링크 발급 가능
- 초대 링크 만료 시간은 24시간
- 워크스페이스에는 하나의 활성 초대 링크만 유지
- 활성 초대 링크가 있으면 링크 복사/조회 시 기존 링크를 재사용
- 명시적으로 초대 링크를 재발급할 때만 기존 링크 자동 무효화
- 초대 링크 조회·발급·복사는 워크스페이스 홈에서만 제공
- 비로그인 사용자도 초대 링크에서 워크스페이스 이름, 대표 이미지 등
  최소 정보는 확인 가능
- 자진 탈퇴한 멤버는 초대 링크로 재참여 가능
- 강제 제거된 멤버는 재초대 불가

### 8.4 멤버 관리

- 일반 멤버와 관리자는 자진 탈퇴 가능
- 소유자는 MVP에서 자진 탈퇴 불가, 워크스페이스 보관으로 대체
- 관리자 강제 제거 가능
- 일반 멤버도 워크스페이스 전체 멤버 목록 조회 가능
- 멤버 목록에는 워크스페이스별 닉네임, 프로필 이미지, 역할을 표시
- 멤버 목록에는 이메일을 노출하지 않음

### 8.5 채널

- `#general` 기본 생성
- 워크스페이스 합류 시 `#general`만 자동 참여
- `#general`은 필수 참여 채널이며 나갈 수 없음
- 공개 채널 지원
- 비공개 채널 지원
- 채널 생성은 소유자/관리자 가능
- 채널 목록은 `#general` 우선, 나머지는 최근 활동 순으로 노출
- 채널 화면에는 채널 참여·나가기처럼 채널 범위 동작만 제공하며,
  워크스페이스 나가기는 홈에서만 제공
- 공개 채널은 참여/나가기/재참여 지원
- 공개 채널은 워크스페이스 멤버에게 채널 존재가 공개됨
- 공개 채널은 워크스페이스 멤버라면 언제든 자유롭게 참여 가능
- 공개 채널은 참여 전 메시지 미리보기는 제공하지 않음
- 공개 채널 참여 후에는 과거 메시지 전체 조회 가능
- 비공개 채널 멤버 관리는 모든 관리자 가능
- 비공개 채널 생성 시 생성자는 자동 포함되며 초기 멤버를 추가로 선택
  할 수 있음
- 비공개 채널도 자진 나가기를 지원함
- 비공개 채널에서 자진 나간 멤버는 관리자 추가를 통해 재참여 가능
- 공개/비공개 채널 모두 강제 제거된 멤버는 재참여할 수 없음
- 비공개 채널 생성자는 채널 보관 전까지 자진 나가기와 강제 제거를
  허용하지 않음
- 비공개 채널은 비멤버에게 목록과 존재를 노출하지 않음
- 비공개 채널의 멤버 목록은 비멤버에게 공개하지 않음
- 비공개 채널에 새로 추가된 멤버도 과거 메시지 전체 조회 가능
- 채널은 즉시 삭제하지 않고 보관만 지원
- 보관된 채널은 15일 내 복원 가능
- 보관된 채널은 읽기 전용으로 유지
- 보관된 채널의 삭제 예정일은 일반 멤버에게도 노출
- 15일 경과 후 자동 삭제

### 8.6 메시지

- 실시간 텍스트 메시지 송수신
- 최신 메시지 기준 진입
- 과거 메시지는 위로 스크롤하며 로드
- 메시지 목록은 cursor pagination을 사용
- 메시지 cursor 기준값은 `createdAt + messageId` 조합
- 메시지 전송 성공/실패 상태 표시
- 실패 시 재전송 지원
- 입력 중 표시 지원
- 텍스트 없이 첨부만 있는 메시지도 허용
- 본인 메시지만 수정 가능
- 메시지 수정 가능 시간은 제한하지 않음
- 관리자는 모든 멤버의 메시지 삭제 가능
- 소유자의 메시지도 관리자 삭제 가능
- 메시지 삭제 시 타임라인에는 삭제된 메시지 흔적을 남김
- 보관된 채널에서는 메시지 작성, 수정, 삭제를 허용하지 않음
- 읽음 갱신은 REST API로만 처리
- 읽음 상태에 대한 별도 broadcast는 제공하지 않음

### 8.7 파일

- 파일 첨부 지원
- 파일 종류는 대체로 허용
- 메시지 첨부 파일 1개당 최대 20MB
- 프로필 이미지는 이미지 파일만 허용하며 1개당 최대 10MB
- 워크스페이스 대표 이미지는 이미지 파일만 허용하며 1개당 최대 10MB
- 워크스페이스 `OWNER`, `ADMIN`은 대표 이미지를 업로드, 교체, 제거할 수 있음
- 이미지 파일만 기본 미리보기 지원
- 파일 저장소는 외부 오브젝트 스토리지 사용
  - 우선 후보: Cloudflare R2
- Presigned URL 방식으로 직접 업로드/다운로드
- Presigned URL 발급 API는 파일 1개씩만 처리
- Presigned URL 발급 요청값은 `fileName`, `contentType`, `size`를 사용
- 업로드만 완료된 파일은 임시 파일 상태로 관리
- 메시지 생성/수정 시 `fileId`가 연결되어야 최종 첨부로 확정
- 프로필과 워크스페이스 대표 이미지는 수정 시 `fileId`가 연결되어야
  최종 이미지로 확정
- 파일 메타데이터는 애플리케이션 DB에서 관리

### 8.8 공통 API/실시간 계약

- REST API는 공통 응답 envelope를 사용
  - `status`는 int 형식 사용
  - 기본 형태는 `status`, `errorCode`, `message`, `result`를 포함
- validation 실패 응답은 `fieldErrors`를 포함
- 목록 응답 필드명은 `items`가 아니라 `contents`를 사용
- pagination은 요청/응답 모두 공통 구조를 사용
- pagination 방식별 세부 값은 `page.type` 하위 구조에 둠
- cursor는 opaque string 대신 객체 형태로 노출
- 전역 공통 에러 코드는 prefix 없이 사용
  - `INTERNAL_SERVER_ERROR`
  - `INVALID_REQUEST`
  - `VALIDATION_ERROR`
- 도메인 에러 코드는 아래 prefix 체계를 사용
  - `AUTH_*`
  - `WORKSPACE_*`
  - `CHANNEL_*`
  - `MESSAGE_*`
  - `FILE_*`
  - `INVITE_*`
  - `MEMBER_*`
- `COMMON_*`, `VALIDATION_*` 같은 별도 공통 prefix는 두지 않음
- 초대 링크 관련 에러는 저장 테이블명과 무관하게 `INVITE_*`를 사용
- WebSocket은 공통 event envelope를 사용
- 실시간 이벤트 타입은 아래 네 가지만 사용
  - `MESSAGE_CREATED`
  - `MESSAGE_UPDATED`
  - `MESSAGE_DELETED`
  - `TYPING_UPDATED`
- message 이벤트 payload는 부분 변경이 아니라 full snapshot을 전달
- typing 이벤트 payload는 `typingUserIds` 같은 snapshot을 전달
- 이벤트 중복 제거용 `eventId`를 포함
- 클라이언트 중복 제거 기준은 `eventId`
- 메시지 최신성 판단 기준은 `occurredAt`이 아니라
  `payload.message.updatedAt`

### 8.9 프로필

- 계정 기본 표시 이름과 프로필 이미지 지원
- 워크스페이스별 닉네임 지원
- 워크스페이스별 프로필 이미지 지원
- 워크스페이스별 닉네임 중복 허용
- 프로필 이미지는 R2 직접 업로드 후 파일 메타데이터를 프로필에
  연결한다
- 최초 OAuth Provider에서 받은 외부 프로필 이미지는 사용자가 직접
  업로드한 R2 이미지로 교체하기 전까지 계정 기본값으로 사용할 수 있다
- 워크스페이스 생성·참여 시 계정 기본 프로필을 멤버십 프로필로 복사
- 계정 기본 프로필과 기존 멤버십 프로필은 복사 이후 독립적으로 수정

### 8.10 안읽음/알림

- 채널 단위 안읽음 배지 지원
- 채널별 읽지 않은 메시지 개수 표시
- 채널 목록 배지만 표시
- 채널 진입 시 해당 시점까지 자동 읽음 처리
- 인앱 푸시 없음
- 브라우저 알림 없음

## 9. 권한 정책 요약

- 소유자:
  - 관리자 권한 포함
  - 관리자 임명/해제
  - 워크스페이스 보관
- 관리자:
  - 채널 생성
  - 초대 링크 발급
  - 멤버 강제 제거
  - 비공개 채널 멤버 관리
  - 메시지 삭제
- 일반 멤버:
  - 메시지 작성
  - 본인 메시지 수정
  - 자진 탈퇴

## 10. UX 원칙

- 카카오톡/디스코드처럼 최신 메시지 기준으로 진입한다.
- 채널 협업에 필요한 흐름을 빠르게 완료할 수 있어야 한다.
- 푸시 알림보다 채널 목록 중심의 안읽음 확인에 집중한다.
- 채팅 UX는 직관적으로, 권한 정책은 단순하게 유지한다.
- 활성 워크스페이스에서는 홈에서 전체 현황을 확인한 뒤 채널로 이동한다.
- 보관된 워크스페이스는 홈에서 보관 상태와 복원 가능 여부만 확인할 수
  있어야 하며, 채널은 복원 후 다시 노출한다.

## 11. 데이터/운영 정책

- 워크스페이스와 채널은 보관 후 15일이 지나면 자동 삭제한다.
- 복원은 보관 기간 내에서만 허용한다.
- 워크스페이스 보관 시 내부 채널도 함께 보관 처리한다.
- 파일은 애플리케이션 서버가 아닌 외부 스토리지에 저장한다.
- 메시지 첨부 또는 프로필 이미지로 최종 연결되지 않은 orphan 파일은
  하루 단위 배치로 정리한다.
- 자진 탈퇴한 멤버는 다시 참여할 수 있다.
- 강제 제거된 멤버는 재초대할 수 없다.
